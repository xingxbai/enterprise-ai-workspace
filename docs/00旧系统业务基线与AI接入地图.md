# 旧系统业务基线与 AI 接入地图

> 文档定位：后续 AI 课程的稳定业务底座，不单独作为一节业务开发课。

## 一、为什么先生成旧系统

真实企业通常不是从空白页面开始做 AI，而是在已有客服、CRM、知识库和权限系统中增加提效能力。本项目先固定一套未接入 AI 的客服旧系统，后续每节课只关注一个 AI 增量及其调试、调优和上线边界。

旧系统保留人工字段和确定性规则，目的是建立可比较的非 AI 基线。后续必须用同一批业务样本比较 AI 接入前后的质量、耗时、采纳率和成本。

## 二、现有页面与业务能力

| 路由 | 已提供的旧系统能力 | 当前决策方式 |
| --- | --- | --- |
| `/` | 工单指标、待处理队列、规则提醒、团队负载、最近操作 | 普通代码统计和固定规则 |
| `/tickets` | 工单查询、状态/优先级筛选、列表与详情导航 | 客服人工分类和设置优先级 |
| `/tickets/[ticketId]` | 问题描述、时间线、负责人、SLA、客户档案、相关知识 | 人工阅读、同分类知识匹配 |
| `/customers` | 客户合同、行业、区域、健康度、未结工单 | 运营人工维护健康度 |
| `/customers/[customerId]` | 客户档案和关联工单 | 确定性 ID 关联 |
| `/knowledge` | 关键词搜索、标签、状态、有效性反馈 | 字符串包含匹配和人工分类 |
| `/team` | 团队负载与角色权限矩阵 | 业务权限配置 |
| `/audit` | 操作人、资源、动作、结果和脱敏详情 | 普通业务审计 |

共享工作区布局在 `src/app/(workspace)/layout.tsx`，默认保持 Server Component；只有需要当前路径高亮的导航叶子是 Client Component。

## 三、数据边界

- 工单摘要通过 `src/data/tickets.ts` 的业务 API Adapter 获取。配置真实 `TICKETS_API_BASE_URL` 时优先请求真实接口。
- 开发环境中，读取型业务 API 缺失或不可用时可以降级到明确标注的 demo fixture，并只记录白名单诊断字段。
- 客户、知识库、团队和业务审计当前使用 `src/data/legacySystem.ts` 中的课程 demo fixture；生产环境自动返回空集合，不会把演示数据当成真实业务数据。
- 当前没有接入真实数据库，因此旧系统基线只提供可信的读取流程。写入操作不能用内存修改或固定成功响应冒充真实落库；接入真实业务 API 后再开放。
- AI API Key、模型名、Base URL、完整 Prompt 和权限判断不属于业务 DTO，也不能传给浏览器。

## 四、逐页接入 AI

### 工单列表

Day12 已完成第一接入点：浏览器只提交 `ticketId`，服务端读取最小工单字段，由模型输出受 Schema 约束的分类、优先级、SLA 风险等级、证据和“无法判断”结果。页面只展示建议，不直接覆盖人工字段。

后续继续加入批量调用、并发、Token/延迟/成本统计、Provider 对照、人工确认和预测效果闭环。

### 工单详情

接入摘要、回复建议、下一步动作和知识引用。生成结果必须可编辑，真实发送或修改工单前必须再次鉴权并由人工确认。

### 客户详情

基于客户档案和关联工单识别意图、情绪、升级风险及依据。模型自报 `confidence` 不等于真实概率；未经评测集校准时只展示风险等级、证据和不确定性。

### 知识库

把关键词搜索逐步演进为文档归一化、Chunk、Embedding、混合检索、Rerank 和带权限引用的 RAG。调试时必须区分没有召回、召回错误、上下文错误、生成未引用和原知识错误。

### 服务工作台

确定性数字继续由业务代码计算，模型只负责解释已验证指标、总结趋势或生成预测结论，不能让模型凭 Prompt 编造统计值。

### 团队权限与审计

AI 权限、模型配额、写入确认、Token、延迟、成本、完成原因、失败层级和采纳反馈都落在现有权限与审计页面，不额外创建脱离业务的 AI 管理 Demo。

## 五、每课 60 分钟的完成定义

每节课只选择上面一个接入点，并同时完成：

1. 说明当前非 AI 基线、AI 目标和可量化指标。
2. 找到页面、最小 DTO、AI BFF、应用服务、Provider、输出 Schema 和审计链路。
3. 交付一个能被下一课继续演进的 AI 增量。
4. 复现一个真实失败样本，并按层定位原因。
5. 至少完成一次固定样本、单变量的调试或调优对照。
6. 手动验证正常、异常、取消/超时、安全和空状态。
7. 形成一段能在面试中解释业务价值、架构边界和技术取舍的项目表达。

## 六、旧 AI 源码的处理

Day4～Day10 已完成的 AI BFF、Provider Adapter、Streaming 和 UI 消息协议源码暂时保留，方便后续迁移到具体旧系统页面。Day12 只在工单列表开放结构化预测入口；其他页面仍保持非 AI 基线。

后续迁移完成后，再删除被成熟链路替代的旧组件；不提前删除仍具有课程演进价值的代码，也不长期保留两套并行实现。

## 七、手动验收

- 登录后能访问工作台、工单、客户、知识库、团队权限和审计页面。
- 工单与知识库搜索、工单筛选、详情跳转和移动端导航可用。
- 未配置真实工单 API 时，开发环境展示 demo fixture；生产环境不展示演示业务数据。
- 页面上没有 AI 生成、模型选择、Provider 状态或“假 AI”结果入口。
- 任意未知工单或客户 ID 返回 404。
- `pnpm typecheck`、`pnpm lint` 和 `git diff --check` 通过；已知保留的 `replaySchema` 未使用警告除外。
